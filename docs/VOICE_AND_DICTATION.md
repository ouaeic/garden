# Voice and dictation

Dictation records a message and returns text to the ask bar. Its setup shows the selected transcription model, retention route and price information before microphone access. A recording is decoded in memory by the installed native media tools; the verified route price and its measured audio duration or full-model token bound determine the spending reservation. The decoder accepts only the chosen audio container and pipe input, with no file or network protocol.

The request is bound to the reviewed provider connection and model. Changing either while recording requires a fresh review. Native OpenAI and OpenRouter transcription use the same account credentials and media adapter as task transcription. OpenRouter transcription requires explicit external retention consent for each recording: its transcription endpoint does not enforce the per-request routing policies used by chat. A generic private endpoint listing does not establish private transcription. The owner’s global provider and privacy settings remain unchanged. Routes need a verified whole-request cost bound. Native token-priced models use their full context and output bounds; an arbitrary owner reservation cannot make an unbounded route eligible. External retention requires explicit selection and consent bound to the reviewed connection; private routing is never silently downgraded.

OpenRouter duration pricing is accepted only when every listed endpoint has a documented billing unit. The reservation uses the highest normalized duration price across those endpoints, including temporarily unavailable ones; it does not rely on the model feed’s cheapest price or pretend to pin a provider. Unknown units and unbounded token routes remain unavailable. This follows the official [transcription protocol](https://openrouter.ai/docs/guides/overview/multimodal/stt) and [Whisper billing units](https://openrouter.ai/openai/whisper-1/providers), [Whisper Large V3 provider units](https://openrouter.ai/openai/whisper-large-v3/) and [Groq billing minima](https://console.groq.com/docs/speech-to-text).

An atomic reservation is recorded before sending audio. A provider receipt settles it before the transcript is returned, including charged responses containing no speech. A confirmed rejection releases it. An uncertain provider outcome leaves the reservation held and the same request cannot submit the recording again. Successful retries return the encrypted cached response; raw recordings are not saved.

Held dictation charges appear under audio receipt recovery. The signed-in owner can reconcile one using the actual cost and an invoice reference. This cannot run while the original request may still return a receipt, cannot touch another owner's charge, and does not send anything to a model. The invoice reference is encrypted before storage.

[Live voice](LIVE_VOICE.md) is a separate browser audio session. Its model, retention, session limit and spending limit are chosen explicitly. Requested task work is presented as a proposal and requires confirmation in the browser before it enters the normal task workflow and approval floor.
